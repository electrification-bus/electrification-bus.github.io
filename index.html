eBus Framework Principles

eBus is built on open, standard protocols that are practical to implement on everything from microcontrollers to full Linux systems.

IP Networking

  • Ethernet
  • Wi-Fi
  • Thread

Standard IP networking provides the foundation. Hardwired Ethernet is preferred for reliability; Wi-Fi and Thread offer flexibility where needed.

Network Discovery

  • Multicast DNS (mDNS)

Devices advertise their existence and capabilities via mDNS, and discover other devices automatically by listening for broadcasts.

Publish/Subscribe Messaging

  • MQTT
  • Homie

Publish/subscribe first. Devices publish state to MQTT topics; others subscribe to what they need. The Homie Convention provides standardized topic structure with self-describing schemas, datatypes, units of measure, and device lifecycle management.

REST APIs

  • HTTP & JSON

REST APIs complement pub/sub when complex request/response semantics are needed, or for device configuration and administration tasks.

Self-Documenting Introspectable APIs

  • Homie Description Schema
  • OpenAPI
  • JSON Schema

Devices publish their interface specifications locally, enabling automatic discovery and integration without external documentation.

Security

  • TLS & mTLS

Secure authentication and authorization for control of home power and energy. Measurements and state have significant privacy implications.

1

Discover

Devices find each other on the local network via mDNS broadcasts

2

Connect

Devices connect to the local MQTT broker (or bridge their own)

3

Publish

Each device publishes its status, state, and measurements to topics

4

Coordinate

Devices subscribe to topics they need and send commands to coordinate

Comparison to Other Standards

eBus focuses specifically on Home Energy Infrastructure device interoperability. It complements rather than competes with other standards.

🏠

Not General IoT

eBus is not for general smart home devices like lights, locks, or sensors. The Matter standard serves that space well. eBus endorses & anticipates that high-load home appliances will support Matter energy management, especially the "Device Energy Management" cluster. eBus focuses on the home's critical electrical infrastructure: batteries, solar, panels, and meters.

⚡

Not Grid Coordination

eBus is not for utility-to-customer demand response signaling. Standards like OpenADR-3 and IEEE 2030.5 handle that domain. eBus enables local device coordination once signals are received.

eBus Embraces Other Standards

eBus adapters bridge to other protocols, enabling integration with devices that use different standards. Any eBus device (a "rider") can integrate with non-eBus devices ("pedestrians") by any means necessary, then publish that data to the eBus broker using the Homie convention.

Once one rider adapts a pedestrian device, all eBus riders benefit. Adapters can be implemented by anyone, anywhere on the home LAN.

Matter

Bridge Matter-enabled thermostats and devices to eBus. Read HVAC status and send commands to adjust setpoints and modes for energy shifting.

Learn more

CTA-2045

Control water heaters and other appliances with EcoPort interfaces. The adapter translates CTA-2045 binary messages to eBus/Homie topics, enabling HEMS to send shed and load-up commands.

Learn more

Legacy Devices

Poll REST APIs or communicate via Modbus/RS-485 with existing devices, then proxy their data to eBus topics.
